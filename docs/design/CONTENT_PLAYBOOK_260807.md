## 2. Usage Rules

1. 이 문서의 "Generation Contract" 섹션이 유일한 구조 SSOT다 — 코드나 다른 문서에 같은 구조를 중복 서술하지 않는다.
2. 구조(8단계 순서)는 고정하되, Hook 문구·사례·화면·표현·CTA 키워드는 매번 다르게 작성한다.
3. Evidence를 확보하지 못하면 생성하지 않고 HOLD한다(추정으로 채우지 않는다).
4. 이 문서를 수정하면 즉시 모든 신규 생성 캡션에 반영된다(코드 재배포 불필요, Runtime 재시작도 불필요 — 매 호출마다 파일을 다시 읽는다).

## Generation Contract

**260810 회장 지시로 전면 개정 — 이전(260807~260808) 8단계 HOOK/PATTERN/LOSS/CAUSE/EVIDENCE/WORKFLOW/RESULT/CTA 구조는 폐기한다.** 실제 게시된 캡션 3건을 회장이 검토한 결과 "내용이 깊이가 없다·겉돈다·클릭·팔로우하고 싶은 글이 아니다·친밀감이 없다"는 지적을 받았다 — 근본 원인은 Evidence를 core_message 한 줄로만 제한하고 Workflow를 추상적인 "입력→자동화→결과" 틀에 억지로 채우게 강제해, Sourcebook에 실제로 있는 구체적 사실(세부 인사이트·실제 기업명 등)이 캡션에 전혀 반영되지 못했기 때문이다(상세: `porting_logs/MERGE_JOURNAL.md` 260810 기록).

또한 이 시점까지 모든 캡션이 CTA로 "프로필 링크 클릭"을 안내해 왔으나, Instagram Graph API로 직접 확인한 결과 계정에 **프로필 링크(website 필드)가 아예 설정돼 있지 않음**이 드러났다 — 지금까지의 CTA는 존재하지 않는 목적지를 안내하고 있었다. 이 프로젝트가 이미 구축·운영 중인 실제 리드 채널은 DM(Webhook 수신→자동응답→CRM)이므로, CTA는 프로필 링크 대신 DM으로 고정한다.

### 신규 구조 (9개 필드 + 고정 CTA, 회장이 직접 예시 2건을 승인한 형식)

구조(반드시 이 순서로 조립한다):

1. **공감 도입 3줄** — 타깃 고객의 답답한 현실을 짧은 문장 조각으로 공감(1줄) → 성공한 계정/기업은 실제로 뭘 하는지 궁금증을 유발하는 질문(2줄, `?`로 끝남) → 의외로 단순하다는 반전 공개(3줄, `!`로 끝남).
2. **`1.How?`** (고정 제목) — 검증된 원천에서 가져온 구체적 사실·방법 2가지를 `•` 불릿으로 나열한다.
3. **`2.{주제별 제목}`** — 이 게시물 주제에 맞는 짧은 제목(예: "구체적 방향", "전제 조건", "핵심 인사이트" 등 매번 다르게)을 붙이고, `:` 다음 한 줄에 원천의 구체적 항목들을 ` · `(가운데 점)으로 구분해 나열한다.
4. **`3.핵심은?`** (고정 제목) — `:` 다음 한 줄로 가장 중요한 한 가지 결론을 제시한다(필요시 ` · `로 대비 구조 표현 가능).
5. **모토 문장** — 큰따옴표로 감싼, 짧고 기억에 남는 핵심 통찰 한 줄.
6. **CTA(고정)** — 모델이 생성하지 않고 코드가 항상 다음 문장을 그대로 붙인다: `더 나누고싶은건 댓글, 더 궁금하면 DM ^_~`

승인된 예시 2건(그대로 게시 가능한 완성형):

```
콘텐츠 하나 만드는 데도 매번 진 다 빠지는 이 느낌....
근데 잘나가는 계정들은 콘텐츠를 새로 만들지 않고 과연 뭘 하길래?
놀랍게도 하나를 여러 번 우려먹고 있다는 사실!

1.How?
• 크로스포스팅 · 리포스팅 · 리퍼포징, 이 셋을 구분해서 쓴다는 것
• 장문 콘텐츠 1개로 최소 5개의 포스트를 뽑아낸다는 것

2.구체적 변환 방향
: 블로그 → SNS 스니펫 · 블로그 → 인포그래픽 · 긴 영상 → 숏폼 · 긴 영상 → 팟캐스트

3.핵심은?
: 모든 채널에 다 뿌리는 게 아니라 · 지금 실제로 살아있는 채널에만 집중한다는 것

"콘텐츠는 새로 짜내는 게 아니라, 이미 있는 것부터 다시 쪼개는 것"

더 나누고싶은건 댓글, 더 궁금하면 DM ^_~
```

```
인스타 DM 문의, 아직도 감으로 하나하나 답하고 계신가요....
근데 이걸 Meta가 이미 공식 기능으로 만들어 뒀다는 거 알고 계셨나요?
놀랍게도 감이 아니라 정해진 구조로 처리하는 영역이었다는 사실!

1.How?
• 템플릿 · 빠른응답 · 대화 라우팅 · 상담원 이관, 이렇게 구조화된 기능으로 처리한다는 것
• 이 전부가 Meta 공식 개발자 문서에 명시돼 있다는 것

2.전제 조건
: 인스타그램 비즈니스 또는 크리에이터 계정이 · Facebook 페이지와 연결돼 있어야 한다는 것

3.핵심은?
: DM 대응은 감이 아니라 · 이미 정해진 시스템으로 옮길 수 있는 영역이라는 것

"인스타 DM은 감으로 버티는 게 아니라, 구조로 옮기는 것"

더 나누고싶은건 댓글, 더 궁금하면 DM ^_~
```

필수 규칙:

- 도입 3줄·How 2개·주제별 제목+본문·핵심 한 줄·모토, 총 9개 필드를 전부 채운다 — 하나라도 빠지면 HOLD.
- 모든 구체적 사실(How 2개, 주제별 제목의 본문, 핵심 한 줄, 모토)은 전달받은 공식 원천(Sourcebook 검증된 설명 전체 — core_message 한 줄로 제한하지 않는다)에 실제로 적힌 내용만 사용한다. 원천에 없는 수치·성과·사례를 새로 만들지 않는다.
- 실제로 전달받지 않은 스크린샷·Runtime 결과·실행 화면을 확인한 것처럼 주장하지 않는다(260808 4차 지시 계승).
- CTA는 모델이 생성하지 않는다 — 항상 고정 문구(`더 나누고싶은건 댓글, 더 궁금하면 DM ^_~`)를 코드가 붙인다. 프로필 링크를 CTA로 쓰지 않는다(프로필 링크 미설정 확인됨).
- `1.How?`/`3.핵심은?` 제목은 고정, `2.{제목}`만 주제에 맞게 매번 다르게 작성한다.
- 여러 항목을 나열할 때는 문장으로 풀지 않고 ` · `(가운데 점)로 구분해 한눈에 스캔 가능하게 한다.
- 도입부는 "질문 던지기 → 놀랍게도 단순하다는 반전 → How? → 답 공개" 순서의 궁금증 구조를 지킨다.
- 문장은 짧고 끊어지는 형태를 쓴다 — 모토·마무리 문장은 완전한 격식체보다 명사형으로 끊는 임팩트 있는 마무리를 우선한다.
- 최종 결과물(9개 필드+고정 CTA+해시태그 합산)은 500자를 넘으면 게시하지 않고 HOLD한다(Threads 공식 게시물 글자수 제한 기준 — [Meta 공식 문서](https://developers.facebook.com/documentation/threads/posts)). 승인된 예시 2건은 고정 CTA 포함 각각 약 373자·394자(해시태그 제외)였다 — 해시태그를 위한 여유를 남기도록 9개 필드 합계를 대략 420자 이내로 유지하는 것을 권장 목표로 한다.
- Evidence를 원천에서 확보하지 못하면 생성하지 말고 HOLD한다.
